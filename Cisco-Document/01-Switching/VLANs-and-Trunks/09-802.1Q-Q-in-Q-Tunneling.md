# 802.1Q Q-in-Q Tunneling

**한국어** | [English](README/09-802.1Q-Q-in-Q-Tunneling.en.md) | [日本語](README/09-802.1Q-Q-in-Q-Tunneling.ja.md) | [简体中文](README/09-802.1Q-Q-in-Q-Tunneling.zh-CN.md) | [Español](README/09-802.1Q-Q-in-Q-Tunneling.es.md) | [Français](README/09-802.1Q-Q-in-Q-Tunneling.fr.md)

**802.1Q 터널링(Q-in-Q)** 은 Metro Ethernet 사업자가 고객에게 **Layer 2 VPN** 을 제공할 때 자주 쓰는 방식입니다. 원리는 단순합니다. 사업자가 고객에게서 받은 **모든 프레임에 802.1Q 태그를 하나 더** 붙입니다. 고객마다 다른 VLAN 태그를 쓰면 고객 트래픽을 서로 분리하면서, 사업자 네트워크를 투명하게 통과시킬 수 있습니다.

| 장점 | 설명 |
| --- | --- |
| 구현이 쉬움 | 특별한 장비 없이 일반 스위치로 가능 |
| 라우팅 불필요 | MPLS VPN과 달리 사업자 ↔ 고객 사이에 라우팅 프로토콜이 필요 없음 |
| 고객 입장 | 두 사이트가 **Layer 2로 직접 연결된 것처럼** 보임 |

> 802.1Q 태그 구조는 [03. 802.1Q Encapsulation](03-802.1Q-Encapsulation.md) 을 먼저 보세요.

---

## 실습 토폴로지

![Q-in-Q lab topology](images/qinq/topology.png)

- **R1, R2**: 고객 사이트 (고객은 두 사이트 사이에 **VLAN 12** 를 사용)
- **SW1, SW2, SW3**: 서비스 사업자 네트워크 (이 고객의 트래픽은 전부 **VLAN 123** 으로 운반)

## 동작 원리

![Q-in-Q tag flow](images/qinq-tag-flow.svg)

1. R1이 프레임에 **VLAN 12** 태그를 붙여 보냅니다.
2. 사업자 스위치 SW1이 그 위에 **VLAN 123** 태그를 하나 더 붙입니다.
3. SW3를 거쳐 SW2에 도착하면, SW2가 **바깥 태그(123)를 떼고** R1이 보낸 원래의 VLAN 12 프레임을 R2로 전달합니다.

프레임 모양으로 보면 이렇습니다.

![Q-in-Q frame](images/qinq-frame.svg)

| 위치 | 프레임 |
| --- | --- |
| 고객 → SW1 | Tag 12 (Inner, Customer) |
| SW1 ↔ SW3 ↔ SW2 Trunk | **Tag 123 (Outer, Provider)** + Tag 12 |
| SW2 → 고객 | Tag 12 |

## 1. 고객 라우터 설정

R1과 R2는 **서브인터페이스** 를 쓰고, 서브넷 `192.168.12.0/24` 에서 모든 프레임을 **VLAN 12** 로 태깅합니다.

![R1 interface](images/qinq/r1-interface.png)

![R1 sub-interface](images/qinq/r1-subinterface.png)

![R2 interface](images/qinq/r2-interface.png)

![R2 sub-interface](images/qinq/r2-subinterface.png)

```
R1(config)#int g0/0
R1(config-if)#no shut
R1(config-if)#int g0/0.12
R1(config-subif)#encapsulation dot1q 12
R1(config-subif)#ip add 192.168.12.1 255.255.255.0
```

R2도 같고, IP만 `192.168.12.2` 입니다.

## 2. 사업자 스위치 사이 Trunk

SW1 – SW3, SW2 – SW3 사이를 **802.1Q Trunk** 로 설정합니다.

![SW1 trunk](images/qinq/sw1-trunk-config.png)

![SW2 trunk](images/qinq/sw2-trunk-config.png)

![SW3 trunk](images/qinq/sw3-trunk-config.png)

```
SW1(config)#int g0/1
SW1(config-if)#sw tr encap dot1q
SW1(config-if)#sw mo tr
```

## 3. Q-in-Q 터널 설정

이제 진짜 "Q-in-Q" 부분입니다. 고객 라우터를 향한 인터페이스에서 들어오는 모든 것을 **VLAN 123** 으로 한 번 더 태깅합니다.

![SW1 dot1q-tunnel](images/qinq/sw1-dot1q-tunnel.png)

![SW2 dot1q-tunnel](images/qinq/sw2-dot1q-tunnel.png)

```
SW1(config)#int g0/0
SW1(config-if)#switchport access vlan 123
SW1(config-if)#switchport mode dot1q-tunnel
```

| 명령어 | 의미 |
| --- | --- |
| `switchport mode dot1q-tunnel` | 이 포트로 들어오는 트래픽에 태그를 **하나 더** 붙임 |
| `switchport access vlan 123` | 바깥에 붙일 **Q-in-Q VLAN(123)** 지정 |

VLAN 123은 **SW1, SW2, SW3 모두** 에 있어야 합니다. SW1, SW2는 access VLAN으로 지정할 때 자동으로 만들어졌지만(`% Access VLAN does not exist. Creating vlan 123`), 중간의 SW3는 직접 만들어야 합니다.

![SW3 vlan 123](images/qinq/sw3-vlan-123.png)

사업자 스위치가 고객 프레임을 정말 터널링하고 있는지는 **스위치 사이 Trunk** 를 보면 확실합니다.

![SW1 show interfaces trunk](images/qinq/sw1-show-trunk.png)

![SW2 show interfaces trunk](images/qinq/sw2-show-trunk.png)

![SW3 show interfaces trunk](images/qinq/sw3-show-trunk.png)

`Vlans allowed and active in management domain` 에는 VLAN 1을 빼면 **123** 만 있습니다. **VLAN 12는 보이지 않습니다.** 고객 트래픽은 VLAN 123 안에 캡슐화되어 있기 때문입니다.

### 4-4. Spanning-tree에도 VLAN 12는 없다

![SW1 spanning-tree vlan 12](images/qinq/sw1-stp-vlan12.png)

![SW2 spanning-tree vlan 12](images/qinq/sw2-stp-vlan12.png)

## 5. Layer 2 프로토콜 터널링

802.1Q 터널링은 고객의 **Layer 2 프로토콜** 도 사업자 네트워크 너머로 넘겨 줄 수 있습니다.

![l2protocol-tunnel options](images/qinq/l2protocol-tunnel-options.png)

| 옵션 | 터널링 대상 |
| --- | --- |
| `cdp` | Cisco Discovery Protocol |
| `lldp` | Link Layer Discovery Protocol |
| `stp` | Spanning Tree Protocol |
| `vtp` | VLAN Trunking Protocol |
| `point-to-point` | PAgP, LACP 같은 point-to-point 프로토콜 (EtherChannel) |
| `drop-threshold` / `shutdown-threshold` | 프로토콜 패킷 수 기준으로 drop / shutdown |

예를 들어 CDP를 터널링하면 사업자 스위치를 사이에 두고도 R1과 R2가 서로를 CDP 이웃으로 볼 수 있습니다.

```
SW1(config-if)#l2protocol-tunnel cdp
```

---

## 핵심 정리

- Q-in-Q = 고객 태그(**Inner**) 위에 사업자 태그(**Outer**)를 하나 더 붙이는 **Layer 2 VPN**.
- 고객 쪽 포트: `switchport mode dot1q-tunnel` + `switchport access vlan <사업자 VLAN>`.
- 사업자 VLAN은 경로 위의 **모든 스위치** 에 있어야 함 (중간 스위치는 직접 생성).
- 사업자 Trunk와 Spanning-tree에는 **고객 VLAN(12)이 보이지 않고** 사업자 VLAN(123)만 보임.
- `l2protocol-tunnel` 로 CDP / LLDP / STP / VTP / LACP·PAgP 도 터널링 가능.
