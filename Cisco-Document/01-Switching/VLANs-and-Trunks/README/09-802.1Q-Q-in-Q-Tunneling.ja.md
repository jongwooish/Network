# 802.1Q Q-in-Q Tunneling

[한국어](../09-802.1Q-Q-in-Q-Tunneling.md) | [English](09-802.1Q-Q-in-Q-Tunneling.en.md) | **日本語** | [简体中文](09-802.1Q-Q-in-Q-Tunneling.zh-CN.md) | [Español](09-802.1Q-Q-in-Q-Tunneling.es.md) | [Français](09-802.1Q-Q-in-Q-Tunneling.fr.md)

**802.1Q トンネリング(Q-in-Q)** は、Metro Ethernet 事業者が顧客に **Layer 2 VPN** を提供するときによく使われる方式です。仕組みはシンプルで、事業者は顧客から受け取った **すべてのフレームに 802.1Q タグをもう 1 つ** 付けます。顧客ごとに別の VLAN タグを使えば、顧客トラフィックを分離しつつ、事業者ネットワークを透過的に通せます。

| メリット | 説明 |
| --- | --- |
| 導入が簡単 | 特別な機器は不要で、一般的なスイッチで実現できる |
| ルーティング不要 | MPLS VPN と違い、事業者 ↔ 顧客間にルーティングプロトコルが要らない |
| 顧客から見ると | 2 拠点が **Layer 2 で直接つながっているように** 見える |

> 802.1Q タグの構造は先に [03. 802.1Q Encapsulation](../03-802.1Q-Encapsulation.md) を参照してください。

---

## ラボ構成

![Q-in-Q lab topology](../images/qinq/topology.png)

- **R1, R2**: 顧客拠点(顧客は拠点間で **VLAN 12** を使用)
- **SW1, SW2, SW3**: サービス事業者ネットワーク(この顧客のトラフィックはすべて **VLAN 123** で運ぶ)

## 動作の仕組み

![Q-in-Q tag flow](../images/qinq-tag-flow.svg)

1. R1 がフレームに **VLAN 12** のタグを付けて送信します。
2. 事業者スイッチ SW1 がその上に **VLAN 123** のタグをもう 1 つ付けます。
3. SW3 を経由して SW2 に届くと、SW2 が **外側のタグ(123)を外し**、R1 が送った元の VLAN 12 フレームを R2 へ転送します。

フレームで見るとこうなります。

![Q-in-Q frame](../images/qinq-frame.svg)

| 場所 | フレーム |
| --- | --- |
| 顧客 → SW1 | Tag 12(Inner、顧客) |
| SW1 ↔ SW3 ↔ SW2 トランク | **Tag 123(Outer、事業者)** + Tag 12 |
| SW2 → 顧客 | Tag 12 |

## 1. 顧客ルーターの設定

R1 と R2 は **サブインターフェイス** を使い、サブネット `192.168.12.0/24` ですべてのフレームを **VLAN 12** でタギングします。

![R1 interface](../images/qinq/r1-interface.png)

![R1 sub-interface](../images/qinq/r1-subinterface.png)

![R2 interface](../images/qinq/r2-interface.png)

![R2 sub-interface](../images/qinq/r2-subinterface.png)

```
R1(config)#int g0/0
R1(config-if)#no shut
R1(config-if)#int g0/0.12
R1(config-subif)#encapsulation dot1q 12
R1(config-subif)#ip add 192.168.12.1 255.255.255.0
```

R2 も同じで、IP だけ `192.168.12.2` です。

---

## 2. 事業者スイッチ間のトランク

SW1 – SW3、SW2 – SW3 の間を **802.1Q トランク** に設定します。

![SW1 trunk](../images/qinq/sw1-trunk-config.png)

![SW2 trunk](../images/qinq/sw2-trunk-config.png)

![SW3 trunk](../images/qinq/sw3-trunk-config.png)

```
SW1(config)#int g0/1
SW1(config-if)#sw tr encap dot1q
SW1(config-if)#sw mo tr
```

---

## 3. Q-in-Q トンネルの設定

ここが本当の「Q-in-Q」部分です。顧客ルーター向けのインターフェイスから入ってくるものすべてに、**VLAN 123** のタグをもう一度付けます。

![SW1 dot1q-tunnel](../images/qinq/sw1-dot1q-tunnel.png)

![SW2 dot1q-tunnel](../images/qinq/sw2-dot1q-tunnel.png)

```
SW1(config)#int g0/0
SW1(config-if)#switchport access vlan 123
SW1(config-if)#switchport mode dot1q-tunnel
```

| コマンド | 意味 |
| --- | --- |
| `switchport mode dot1q-tunnel` | このポートに入るトラフィックにタグを **もう 1 つ** 付ける |
| `switchport access vlan 123` | 外側に付ける **Q-in-Q VLAN(123)** を指定 |

VLAN 123 は **SW1、SW2、SW3 のすべて** に必要です。SW1 と SW2 は access VLAN に指定した時点で自動作成されました(`% Access VLAN does not exist. Creating vlan 123`)が、中間の SW3 では手動で作成する必要があります。

![SW3 vlan 123](../images/qinq/sw3-vlan-123.png)

## 4. 確認

### 4-1. Ping

![R1 ping](../images/qinq/r1-ping.png)

R1 → R2 の ping 成功(5/5)。

### 4-2. `show dot1q-tunnel`

![SW1 show dot1q-tunnel](../images/qinq/sw1-show-dot1q-tunnel.png)

![SW2 show dot1q-tunnel](../images/qinq/sw2-show-dot1q-tunnel.png)

このコマンドの情報は多くありません。**dot1q-tunnel に設定されたインターフェイス** だけが表示されます。

### 4-3. トランクには VLAN 123 しか見えない

事業者スイッチが顧客フレームを本当にトンネリングしているかは、**スイッチ間のトランク** を見れば確実です。

![SW1 show interfaces trunk](../images/qinq/sw1-show-trunk.png)

![SW2 show interfaces trunk](../images/qinq/sw2-show-trunk.png)

![SW3 show interfaces trunk](../images/qinq/sw3-show-trunk.png)

`Vlans allowed and active in management domain` には VLAN 1 を除くと **123** しかありません。**VLAN 12 は見えません。** 顧客トラフィックは VLAN 123 の中にカプセル化されているからです。

### 4-4. Spanning-tree にも VLAN 12 はない

![SW1 spanning-tree vlan 12](../images/qinq/sw1-stp-vlan12.png)

![SW2 spanning-tree vlan 12](../images/qinq/sw2-stp-vlan12.png)

![SW3 spanning-tree vlan 12](../images/qinq/sw3-stp-vlan12.png)

3 台とも `Spanning tree instance(s) for vlan 12 does not exist.` です。事業者スイッチは **顧客がどの VLAN を使っているかを気にせず**、VLAN 123 だけを見ています。

## 5. Layer 2 プロトコルのトンネリング

802.1Q トンネリングは、顧客の **Layer 2 プロトコル** も事業者ネットワークの向こう側へ運べます。

![l2protocol-tunnel options](../images/qinq/l2protocol-tunnel-options.png)

| オプション | トンネリング対象 |
| --- | --- |
| `cdp` | Cisco Discovery Protocol |
| `lldp` | Link Layer Discovery Protocol |
| `stp` | Spanning Tree Protocol |
| `vtp` | VLAN Trunking Protocol |
| `point-to-point` | PAgP、LACP などの point-to-point プロトコル(EtherChannel) |
| `drop-threshold` / `shutdown-threshold` | プロトコルパケット数を基準に drop / shutdown |

たとえば CDP をトンネリングすると、事業者スイッチを挟んでいても R1 と R2 が互いを CDP ネイバーとして認識できます。

```
SW1(config-if)#l2protocol-tunnel cdp
```

---

## まとめ

- Q-in-Q = 顧客タグ(**Inner**)の上に事業者タグ(**Outer**)をもう 1 つ付ける **Layer 2 VPN**。
- 顧客側ポート: `switchport mode dot1q-tunnel` + `switchport access vlan <事業者 VLAN>`。
- 事業者 VLAN は経路上の **すべてのスイッチ** に必要(中間スイッチでは手動作成)。
- 事業者トランクと Spanning-tree には **顧客 VLAN(12)は見えず**、事業者 VLAN(123)だけが見える。
- `l2protocol-tunnel` で CDP / LLDP / STP / VTP / LACP・PAgP もトンネリング可能。
