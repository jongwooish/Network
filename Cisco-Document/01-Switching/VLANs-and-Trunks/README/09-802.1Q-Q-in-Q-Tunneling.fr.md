# 802.1Q Q-in-Q Tunneling

[한국어](../09-802.1Q-Q-in-Q-Tunneling.md) | [English](09-802.1Q-Q-in-Q-Tunneling.en.md) | [日本語](09-802.1Q-Q-in-Q-Tunneling.ja.md) | [简体中文](09-802.1Q-Q-in-Q-Tunneling.zh-CN.md) | [Español](09-802.1Q-Q-in-Q-Tunneling.es.md) | **Français**

Le **tunneling 802.1Q (Q-in-Q)** est souvent utilisé par les opérateurs Metro Ethernet pour offrir à leurs clients un **VPN de niveau 2**. Le principe est simple : l'opérateur ajoute **une étiquette 802.1Q supplémentaire à chaque trame** reçue du client. Avec une étiquette VLAN différente par client, il sépare le trafic de chacun et le transporte de manière transparente dans son réseau.

| Avantage | Description |
| --- | --- |
| Facile à mettre en place | Fonctionne sur des switchs ordinaires, sans matériel spécial |
| Pas de routage | Contrairement au MPLS VPN, aucun protocole de routage entre l'opérateur et le client |
| Vu par le client | Les deux sites semblent **directement reliés en niveau 2** |

> Pour la structure de l'étiquette 802.1Q, lisez d'abord [03. 802.1Q Encapsulation](../03-802.1Q-Encapsulation.md).

---

## Topologie du TP

![Q-in-Q lab topology](../images/qinq/topology.png)

- **R1, R2** : sites du client (le client utilise le **VLAN 12** entre ses sites)
- **SW1, SW2, SW3** : réseau de l'opérateur (tout le trafic de ce client est transporté dans le **VLAN 123**)

## Fonctionnement

![Q-in-Q tag flow](../images/qinq-tag-flow.svg)

1. R1 envoie des trames étiquetées **VLAN 12**.
2. Le switch opérateur SW1 ajoute par-dessus une étiquette **VLAN 123**.
3. Après SW3, SW2 **retire l'étiquette extérieure (123)** et transmet à R2 la trame VLAN 12 d'origine envoyée par R1.

Vu sous forme de trames :

![Q-in-Q frame](../images/qinq-frame.svg)

| Où | Trame |
| --- | --- |
| Client → SW1 | Tag 12 (intérieure, client) |
| Trunks SW1 ↔ SW3 ↔ SW2 | **Tag 123 (extérieure, opérateur)** + Tag 12 |
| SW2 → Client | Tag 12 |

## 1. Configuration des routeurs du client

R1 et R2 utilisent des **sous-interfaces** sur le sous-réseau `192.168.12.0/24` et étiquettent toutes les trames en **VLAN 12**.

![R1 interface](../images/qinq/r1-interface.png)

![R1 sub-interface](../images/qinq/r1-subinterface.png)

![R2 interface](../images/qinq/r2-interface.png)

![R2 sub-interface](../images/qinq/r2-subinterface.png)

```
R1(config)#int g0/0
R1(config-if)#no shut
R1(config-if)#int g0/0.12
R1(config-subif)#encapsulation dot1q 12
R1(config-subif)#ip add 192.168.12.1 255.255.255.0
```

R2 est identique, seule l'IP change : `192.168.12.2`.

---

## 2. Trunks entre les switchs de l'opérateur

Configurez des **trunks 802.1Q** entre SW1 – SW3 et SW2 – SW3.

![SW1 trunk](../images/qinq/sw1-trunk-config.png)

![SW2 trunk](../images/qinq/sw2-trunk-config.png)

![SW3 trunk](../images/qinq/sw3-trunk-config.png)

```
SW1(config)#int g0/1
SW1(config-if)#sw tr encap dot1q
SW1(config-if)#sw mo tr
```

## 3. Configuration du tunnel Q-in-Q

Voici la vraie partie « Q-in-Q ». Tout ce qui entre par les interfaces côté routeurs client reçoit une étiquette supplémentaire **VLAN 123**.

![SW1 dot1q-tunnel](../images/qinq/sw1-dot1q-tunnel.png)

![SW2 dot1q-tunnel](../images/qinq/sw2-dot1q-tunnel.png)

```
SW1(config)#int g0/0
SW1(config-if)#switchport access vlan 123
SW1(config-if)#switchport mode dot1q-tunnel
```

| Commande | Signification |
| --- | --- |
| `switchport mode dot1q-tunnel` | Ajoute **une étiquette de plus** au trafic qui entre par ce port |
| `switchport access vlan 123` | Définit le **VLAN Q-in-Q (123)** extérieur |

Le VLAN 123 doit exister sur **SW1, SW2 et SW3**. SW1 et SW2 l'ont créé automatiquement en l'affectant comme VLAN d'accès (`% Access VLAN does not exist. Creating vlan 123`), mais il faut le créer à la main sur SW3, au milieu.

![SW3 vlan 123](../images/qinq/sw3-vlan-123.png)

## 4. Vérification

### 4-1. Ping

![R1 ping](../images/qinq/r1-ping.png)

Le ping R1 → R2 fonctionne (5/5).

### 4-2. `show dot1q-tunnel`

![SW1 show dot1q-tunnel](../images/qinq/sw1-show-dot1q-tunnel.png)

![SW2 show dot1q-tunnel](../images/qinq/sw2-show-dot1q-tunnel.png)

Cette commande donne peu d'informations : elle affiche seulement les **interfaces configurées en dot1q-tunnel**.

### 4-3. Seul le VLAN 123 apparaît sur les trunks

Les **trunks entre les switchs** prouvent que l'opérateur tunnelise réellement les trames du client.

![SW1 show interfaces trunk](../images/qinq/sw1-show-trunk.png)

![SW2 show interfaces trunk](../images/qinq/sw2-show-trunk.png)

![SW3 show interfaces trunk](../images/qinq/sw3-show-trunk.png)

À part le VLAN 1, `Vlans allowed and active in management domain` ne contient que **123**. **Le VLAN 12 n'apparaît pas**, car le trafic client est encapsulé dans le VLAN 123.

### 4-4. Pas de VLAN 12 dans le spanning-tree non plus

![SW1 spanning-tree vlan 12](../images/qinq/sw1-stp-vlan12.png)

![SW2 spanning-tree vlan 12](../images/qinq/sw2-stp-vlan12.png)

![SW3 spanning-tree vlan 12](../images/qinq/sw3-stp-vlan12.png)

Les trois switchs affichent `Spanning tree instance(s) for vlan 12 does not exist.` Les switchs de l'opérateur **ne se soucient pas du VLAN utilisé par le client** ; ils ne voient que le VLAN 123.

## 5. Tunneling des protocoles de niveau 2

Le tunneling 802.1Q peut aussi transporter les **protocoles de niveau 2** du client à travers le réseau de l'opérateur.

![l2protocol-tunnel options](../images/qinq/l2protocol-tunnel-options.png)

| Option | Ce qui est tunnelisé |
| --- | --- |
| `cdp` | Cisco Discovery Protocol |
| `lldp` | Link Layer Discovery Protocol |
| `stp` | Spanning Tree Protocol |
| `vtp` | VLAN Trunking Protocol |
| `point-to-point` | Protocoles point à point comme PAgP et LACP (EtherChannel) |
| `drop-threshold` / `shutdown-threshold` | Rejet / arrêt selon le nombre de paquets du protocole |

Par exemple, en tunnelisant CDP, R1 et R2 se voient comme voisins CDP même avec des switchs opérateur entre eux.

```
SW1(config-if)#l2protocol-tunnel cdp
```

---

## À retenir

- Q-in-Q = un **VPN de niveau 2** qui ajoute l'étiquette opérateur (**extérieure**) par-dessus celle du client (**intérieure**).
- Port côté client : `switchport mode dot1q-tunnel` + `switchport access vlan <VLAN opérateur>`.
- Le VLAN opérateur doit exister sur **tous les switchs** du chemin (à créer à la main sur les switchs de transit).
- Les trunks et le spanning-tree de l'opérateur **ne montrent pas le VLAN client (12)**, seulement le VLAN opérateur (123).
- `l2protocol-tunnel` permet aussi de tunneliser CDP / LLDP / STP / VTP / LACP·PAgP.
