# 802.1Q Q-in-Q Tunneling

[한국어](../09-802.1Q-Q-in-Q-Tunneling.md) | [English](09-802.1Q-Q-in-Q-Tunneling.en.md) | [日本語](09-802.1Q-Q-in-Q-Tunneling.ja.md) | **简体中文** | [Español](09-802.1Q-Q-in-Q-Tunneling.es.md) | [Français](09-802.1Q-Q-in-Q-Tunneling.fr.md)

**802.1Q 隧道(Q-in-Q)** 是城域以太网(Metro Ethernet)运营商为客户提供 **二层 VPN** 时常用的方式。原理很简单:运营商在从客户收到的 **每个帧上再加一层 802.1Q 标签**。每个客户使用不同的 VLAN 标签,就能在隔离客户流量的同时,让流量透明地穿过运营商网络。

| 优点 | 说明 |
| --- | --- |
| 实现简单 | 不需要特殊设备,普通交换机即可 |
| 无需路由 | 与 MPLS VPN 不同,运营商与客户之间不需要路由协议 |
| 客户视角 | 两个站点看起来就像 **在二层直接相连** |

> 802.1Q 标签结构请先阅读 [03. 802.1Q Encapsulation](../03-802.1Q-Encapsulation.md)。

---

## 实验拓扑

![Q-in-Q lab topology](../images/qinq/topology.png)

- **R1、R2**:客户站点(客户在两个站点之间使用 **VLAN 12**)
- **SW1、SW2、SW3**:服务运营商网络(该客户的所有流量都用 **VLAN 123** 承载)

## 工作原理

![Q-in-Q tag flow](../images/qinq-tag-flow.svg)

1. R1 发送带 **VLAN 12** 标签的帧。
2. 运营商交换机 SW1 在其外面再加一个 **VLAN 123** 标签。
3. 经过 SW3 到达 SW2 后,SW2 **去掉外层标签(123)**,把 R1 发出的原始 VLAN 12 帧转发给 R2。

从帧的角度看:

![Q-in-Q frame](../images/qinq-frame.svg)

| 位置 | 帧 |
| --- | --- |
| 客户 → SW1 | Tag 12(内层,客户) |
| SW1 ↔ SW3 ↔ SW2 Trunk | **Tag 123(外层,运营商)** + Tag 12 |
| SW2 → 客户 | Tag 12 |

## 1. 客户路由器配置

R1 和 R2 使用 **子接口**,在子网 `192.168.12.0/24` 上把所有帧打上 **VLAN 12** 标签。

![R1 interface](../images/qinq/r1-interface.png)

![R1 sub-interface](../images/qinq/r1-subinterface.png)

![R2 interface](../images/qinq/r2-interface.png)

![R2 sub-interface](../images/qinq/r2-subinterface.png)

```
R1(config)#int g0/0
R1(config-if)#no shut
R1(config-if)#int g0/0.12
R1(config-subif)#encapsulation dot1q 12
R1(config-subif)#ip add 192.168.12.1 255.255.255.0
```

R2 相同,只是 IP 为 `192.168.12.2`。

---

## 2. 运营商交换机之间的 Trunk

在 SW1 – SW3、SW2 – SW3 之间配置 **802.1Q Trunk**。

![SW1 trunk](../images/qinq/sw1-trunk-config.png)

![SW2 trunk](../images/qinq/sw2-trunk-config.png)

![SW3 trunk](../images/qinq/sw3-trunk-config.png)

```
SW1(config)#int g0/1
SW1(config-if)#sw tr encap dot1q
SW1(config-if)#sw mo tr
```

## 3. Q-in-Q 隧道配置

这才是真正的 "Q-in-Q" 部分。从面向客户路由器的接口进入的所有流量,都再打一层 **VLAN 123** 标签。

![SW1 dot1q-tunnel](../images/qinq/sw1-dot1q-tunnel.png)

![SW2 dot1q-tunnel](../images/qinq/sw2-dot1q-tunnel.png)

```
SW1(config)#int g0/0
SW1(config-if)#switchport access vlan 123
SW1(config-if)#switchport mode dot1q-tunnel
```

| 命令 | 含义 |
| --- | --- |
| `switchport mode dot1q-tunnel` | 给进入该端口的流量 **再加一层** 标签 |
| `switchport access vlan 123` | 指定外层的 **Q-in-Q VLAN(123)** |

VLAN 123 必须在 **SW1、SW2、SW3 上都存在**。SW1 和 SW2 在指定 access VLAN 时自动创建了它(`% Access VLAN does not exist. Creating vlan 123`),但中间的 SW3 需要手动创建。

![SW3 vlan 123](../images/qinq/sw3-vlan-123.png)

## 4. 验证

### 4-1. Ping

![R1 ping](../images/qinq/r1-ping.png)

R1 → R2 ping 成功(5/5)。

### 4-2. `show dot1q-tunnel`

![SW1 show dot1q-tunnel](../images/qinq/sw1-show-dot1q-tunnel.png)

![SW2 show dot1q-tunnel](../images/qinq/sw2-show-dot1q-tunnel.png)

这个命令信息不多,只显示 **配置了 dot1q-tunnel 的接口**。

### 4-3. Trunk 上只看到 VLAN 123

要确认运营商交换机是否真的在隧道传输客户帧,看 **交换机之间的 Trunk** 最直接。

![SW1 show interfaces trunk](../images/qinq/sw1-show-trunk.png)

![SW2 show interfaces trunk](../images/qinq/sw2-show-trunk.png)

![SW3 show interfaces trunk](../images/qinq/sw3-show-trunk.png)

除 VLAN 1 外,`Vlans allowed and active in management domain` 中只有 **123**。**看不到 VLAN 12**,因为客户流量被封装在 VLAN 123 里面。

### 4-4. Spanning-tree 中也没有 VLAN 12

![SW1 spanning-tree vlan 12](../images/qinq/sw1-stp-vlan12.png)

![SW2 spanning-tree vlan 12](../images/qinq/sw2-stp-vlan12.png)

![SW3 spanning-tree vlan 12](../images/qinq/sw3-stp-vlan12.png)

三台交换机都显示 `Spanning tree instance(s) for vlan 12 does not exist.`。运营商交换机 **不关心客户用的是哪个 VLAN**,只关心 VLAN 123。

## 5. 二层协议隧道

802.1Q 隧道还可以把客户的 **二层协议** 送到运营商网络的另一端。

![l2protocol-tunnel options](../images/qinq/l2protocol-tunnel-options.png)

| 选项 | 隧道对象 |
| --- | --- |
| `cdp` | Cisco Discovery Protocol |
| `lldp` | Link Layer Discovery Protocol |
| `stp` | Spanning Tree Protocol |
| `vtp` | VLAN Trunking Protocol |
| `point-to-point` | PAgP、LACP 等点对点协议(EtherChannel) |
| `drop-threshold` / `shutdown-threshold` | 按协议报文数量 drop / shutdown |

例如隧道传输 CDP 后,即使中间隔着运营商交换机,R1 和 R2 也能互相看到对方是 CDP 邻居。

```
SW1(config-if)#l2protocol-tunnel cdp
```

---

## 要点总结

- Q-in-Q = 在客户标签(**内层**)外再加一层运营商标签(**外层**)的 **二层 VPN**。
- 面向客户的端口:`switchport mode dot1q-tunnel` + `switchport access vlan <运营商 VLAN>`。
- 运营商 VLAN 必须存在于路径上的 **所有交换机**(中间交换机需手动创建)。
- 运营商 Trunk 和 Spanning-tree 中 **看不到客户 VLAN(12)**,只看到运营商 VLAN(123)。
- `l2protocol-tunnel` 还可以隧道传输 CDP / LLDP / STP / VTP / LACP·PAgP。
